## Причина и исправление

У опубликованного APK и собранного F-Droid APK совпадают все распакованные файлы,
сжатые потоки и порядок ZIP entries. Различаются поля выравнивания в local
headers и обусловленные ими смещения, например:

- `assets/dexopt/baseline.prof`: подписанный `35d905000400000000`, неподписанный `00`;
- `classes.dex`: подписанный `35d902000400`, неподписанный `0000`.

Build Tools 35 по умолчанию переписывает выравнивание при `apksigner sign`.
В [workflow Release](../../.github/workflows/release.yml) добавлен
`--alignment-preserved true`. Предыдущая проверка `zipalign -c` только проверяла
выравнивание входного APK и не предотвращала его последующее изменение signer.
Поведение подтверждается [документацией apksigcopier](https://github.com/obfusk/apksigcopier#what-about-signatures-made-by-apksigner-from-build-tools--3500-rc1).

Тест с исправленной командой использовал временный RSA-2048/PKCS12 ключ.
Тестовый подписанный APK не является релизом Keyra и не должен публиковаться.
Его положительный результат подтверждает исправление процесса, но не заменяет
повторную проверку APK, выпущенного настоящим ключом через GitHub Actions.

## Следующий шаг

1. Закоммитить исправление workflow и подготовить следующую версию, например
   `0.1.1`, через `prepareRelease`, заполнить оба changelog.
2. Опубликовать её обычным Release workflow с существующим постоянным ключом.
   Не передвигать `v0.1.0` и не подменять APK старого GitHub Release.
3. Повторить проверки с новым тегом/APK. Для первой подачи в fdroiddata включить
   рабочую новую версию; непроходящий build entry `0.1.0` не выдавать за проверенный.
4. После успешного сравнения настоящего релиза подать рецепт в fdroiddata.

## Артефакты и границы проверки

Логи и JSON сохранены локально в
`dist/fdroid-check/results/keyra-verify.QnmWAp/`; они намеренно не добавлены в Git.
Ключевые файлы: `fdroid-build.log`, `fdroid-lint-catalog.log`,
`fdroid-reference-comparison.json`, `linux-vs-fdroid.json`,
`alignment-preserved-smoke.json`, `alignment-preserved-smoke.log`,
`current-tests.json`, `current-app-reports/lint-results-debug.xml`,
`current-repeatability.json`, `environment.txt`, `sources.txt`, `checks.tsv`.

`checks.tsv` сохраняет также неудачные первичные попытки настройки lint:
без каталогов, затем без их иконок. Итоговый повторный lint с полным официальным
каталогом прошёл. Часть этапов была продолжена отдельно в сохранённом окружении
после прерывания первоначального сценария; неудачные логи не удалялись.

Это локальный preflight с настоящими инструментами F-Droid, а не проверка
официальной buildserver VM. Команды `sudo` из рецепта при локальном build
пропускаются; JDK выбран при создании образа. Эмуляторные UI-тесты, официальная
CI fdroiddata и решение сопровождающих в этот результат не входят.
